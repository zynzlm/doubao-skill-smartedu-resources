# 安装说明（WorkBuddy / CodeBuddy）

这个 Skill 在豆包 App 里可以直接用；换到 WorkBuddy 或任何支持 Skill 的宿主时，只需三步装上，然后跑一次依赖安装。下面的命令都不需要登录平台。

## 一、安装（三步）

**第 1 步**：拿到技能文件夹。GitHub 仓：`https://github.com/zynzlm/doubao-skill-smartedu-resources`

选一种：

- 下载 ZIP：仓库首页 → `Code` → `Download ZIP`，解压后取其中的 **`workbuddy` 文件夹**（放的是本文件夹里的 `SKILL.md` 与这份说明，脚本在隔壁 `smartedu-resources/scripts`）。
- 或直接 clone：`git clone https://github.com/zynzlm/doubao-skill-smartedu-resources.git`

**第 2 步**：把文件夹放进宿主的 Skill 目录。

WorkBuddy 与豆包 App 一样，Skill 就是某个目录下的一个文件夹，文件夹名就是 Skill 名，里面必须有 `SKILL.md`：

| 宿主 | 放到哪里 |
|---|---|
| WorkBuddy / CodeBuddy | 用户技能目录下建 `smartedu-resources/`，把 `SKILL.md`、`scripts/`、`references/`、`workbuddy/` 一起放进去 |
| 豆包 App | `工作区/.user_skills/smartedu-resources/` |

最终结构应是：

```text
smartedu-resources/
├─ SKILL.md
├─ README.md
├─ references/api.md
├─ scripts/{setup.py, smartedu.py, fetch_resource.py, batch_download.py, to_pptx.py, pdf_to_md.py, md_to_docx.py, build_docs.py}
└─ workbuddy/{SKILL.md, 安装说明.md}
```

如果宿主只认一层目录（不读 `workbuddy/`），就把 `workbuddy/SKILL.md` 复制成根目录的 `SKILL.md` 即可——它比豆包版多了 `allowed-tools: Read, Write, Bash, Glob`，并与下文“不依赖插件的 Word 路径”对齐；根目录 `scripts/` 保持不动，路径引用一致。

**第 3 步**：重启客户端或在设置里重新加载 Skill 列表，确认 `smartedu-resources` 出现。

## 二、首次使用：跑一次 setup.py

不用手敲 pip，脚本自己检测并安装：

```bash
cd <技能目录>/scripts
python setup.py --check                  # 只看缺什么
python setup.py -y --mirror tsinghua     # 缺什么装什么（-y 不询问）
python setup.py -y --self-test           # 装完逐个跑脚本 --help 自检
```

- 必需包：`pillow`、`pymupdf`、`python-pptx`、`python-docx`、`requests`。
- 走离线 OCR 兜底才需要额外装：`python setup.py -y --local-ocr`（`rapidocr`、`rapid-layout`、`opencv-python-headless`）。
- 退出码 0 = 环境就绪，1 = 仍有依赖没装上（先解决环境再下载）。
- 需要 Python 3.8 及以上；Windows 上命令写 `python`，若提示找不到命令就写 `py -3`。

## 三、常用命令（都在 `scripts/` 目录下跑）

```bash
# 1) 整章下载（例子：人教版八上物理 第五章）
python batch_download.py --teachingmaterial 5370d999-5dd2-4c64-a9ed-089ec2694300 --chapter 第五章 --out "E:\资源网资源\人教版八年级上册物理_第五章 透镜及其应用"

# 2) 课件 PDF → PPTX（只转课件时先按文件名筛）
python to_pptx.py --in "<某节目录>" --out "<PPT输出目录>"

# 3) 文档 PDF → 可编辑 Word（两条命令：先解析出 md，再渲染 docx）
python pdf_to_md.py --engine textin --in "第一节 透镜" --out-dir md     # 需先设 TEXTIN_APP_ID / TEXTIN_SECRET_CODE
python build_docs.py --md "md/作业练习-第1节  透镜.md" --out "<输出目录>" --name "作业练习-第1节 透镜.docx"
```

## 四、转 Word 的两条路径

平台的 PDF 是逐页图片合成的，**没有文字层**，所以必须先解析成 markdown 再渲染成 docx。

### 路径 A（推荐）：TextIn xParse HTTP 接口

豆包 App 用的是 xParse **插件**，WorkBuddy 没有这个插件——这正是“能下载却没出 Word”的原因。修正后的做法是直接走 TextIn 的公开 HTTP 接口，脚本已封装，不需要任何 MCP：

```powershell
# Windows PowerShell 先设凭证
$env:TEXTIN_APP_ID="你的 app-id"; $env:TEXTIN_SECRET_CODE="你的 secret-code"
python pdf_to_md.py --engine textin --pdf "作业练习-第1节  透镜.pdf" --out md/c02.md
```

```bash
# macOS / Linux
export TEXTIN_APP_ID=xxxx; export TEXTIN_SECRET_CODE=yyyy
python pdf_to_md.py --engine textin --pdf "作业练习-第1节  透镜.pdf" --out md/c02.md
```

取 key：打开 `https://www.textin.com` → 工作台 → 账号设置 → 开发者信息。有免费额度（每日 1000 页量级），一个章节够用。凭证错或缺时，脚本会直接打印注册指引（错误码 40101/40102/40103）。

产出与豆包版一致：真表格、插图是可直接下载的 URL，`md_to_docx.py` 会自动取回并插在原位。

### 路径 B：宿主自带版面解析 MCP

如果宿主里已经装了 xParse 一类的 MCP，直接用它把 PDF 解析成 markdown（存到 `<work>/md/cXX.md`），再跑 `build_docs.py`。豆包 App 里的参数是 `result_format=markdown`、`table_view=html`、`include_table_structure=true`、`resource_mode=free_only`。

### 路径 C：本地 OCR 兜底（不联网、不要账号）

```bash
python setup.py -y --local-ocr
python pdf_to_md.py --engine local --pdf "作业练习-第1节  透镜.pdf" --out md/c02.md
```

**质量有限**：版面模型会漏检部分插图（实测一页 7 张图能出 4~5 张）、表格列数与合并可能错、公式上下标失真。只能应急，交付时必须说明“需对照源 PDF 复核”。

## 五、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 依赖报 `ModuleNotFoundError` | 没跑 setup.py | `python setup.py -y --mirror tsinghua` |
| 能下载 PDF，但没生成 docx | 旧版 SKILL.md 只写了豆包插件名，WorkBuddy 没有该插件 | 按上文路径 A 设 `TEXTIN_APP_ID` 后跑 `pdf_to_md.py --engine textin`，再 `build_docs.py` |
| `pdf_to_md.py` 报凭证错误 | `TEXTIN_APP_ID`/`TEXTIN_SECRET_CODE` 未设或填错 | 到 textin.com 工作台取开发者信息，重设环境变量 |
| `pdf_to_docx.py` 出来只有整页图 | 平台 PDF 无文字层 | 改用 `pdf_to_md.py` + `md_to_docx.py`，`pdf_to_docx.py` 已废弃 |
| docx 里插图少了几张 | 路径 C 版面漏检 | 对照源 PDF 手工补裁，或改走路径 A |
| pptx 里混进了教学设计/任务单 | `--in` 传了目录 | 先按 `课件*.pdf` 筛出单个 PDF 再转 |
| 找不到章节 / 资源对不上 | 目录缓存过期 | `python smartedu.py <子命令> --refresh` 重建索引 |
| 视频下载失败 | 视频是 m3u8 流，需登录签名 | 只能登录后在线观看，或自行录屏；不要直连 m3u8 |
| 需登录才能播放/看资源库 | 登录只影响视频与“我的资源库” | 让 Skill 打开浏览器，用户自己登录后交回，脚本路径无需登录 |

## 六、与豆包版 SKILL.md 的差异

| 项 | 豆包版（`smartedu-resources/SKILL.md`） | WorkBuddy 版（本目录 `SKILL.md`） |
|---|---|---|
| frontmatter | 只有 `name`、`description` | 额外 `allowed-tools: Read, Write, Bash, Glob`，保证脚本能执行 |
| 文档转 Word | 首选 xParse 插件（`prepare_file_upload` → `submit_parse_task` → `parse_document`） | 改为 A=TextIn HTTP 接口 / B=宿主自带 MCP / C=本地 OCR 三档，插件不再是必需 |
| 登录交接 | 依赖 `computer_use_tool` + `interaction_request_action` | 改为不限定宿主，打开登录页后交给用户，不代填账号密码 |
| 脚本表 | 含两个废弃脚本提示 | 明确标注 `pdf_to_md.py` 是转 Word 第一步 |
